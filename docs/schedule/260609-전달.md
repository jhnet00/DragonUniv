

## 현재 CRUD 구현 상태

### 구현되어 있는 기능

현재 Backend와 DB 기준으로 구현된 실제 DB 연동 기능은 학생 수강신청 중심이다.

| 화면/기능 | DB 연동 여부 | 설명 |
|-----------|--------------|------|
| 강의 목록 조회 | 구현됨 | `GET /api/courses` |
| 내 수강 목록 조회 | 구현됨 | `GET /api/registrations` |
| 수강신청 | 구현됨 | `POST /api/registrations` |
| 수강취소 | 구현됨 | `DELETE /api/registrations/:classId` |
| DB health check | 구현됨 | `GET /api/health` |

### 아직 구현되지 않은 기능

관리자 강의 관리 화면의 CRUD는 아직 실제 DB와 연결되어 있지 않다.

현재 `AdminCourses.tsx`는 `Frontend/src/data/courses.ts`의 mock data를 테이블로 보여준다.

아직 없는 API:

```txt
POST /api/admin/courses
PUT /api/admin/courses/:classId
DELETE /api/admin/courses/:classId
```

즉, 관리자 UI에서 `Add course`, edit, delete 버튼을 눌러도 실제 DB의 `classes` 테이블에 insert/update/delete가 되는 구조는 아직 아니다.

## 관리자 CRUD를 구현하려면 필요한 작업

### Backend

1. 관리자 강의 목록 API 추가
2. 강의 추가 API 추가
3. 강의 수정 API 추가
4. 강의 삭제 API 추가
5. major 목록 조회 API 추가
6. 요청값 validation 추가
7. 삭제 시 이미 수강신청된 강의 처리 정책 결정

필요 API 예시:

```txt
GET    /api/admin/courses
POST   /api/admin/courses
PUT    /api/admin/courses/:classId
DELETE /api/admin/courses/:classId
GET    /api/majors
```

### Frontend

1. `AdminCourses.tsx`에서 mock data 제거
2. API로 강의 목록 조회
3. Add course 버튼 클릭 시 modal 또는 form 열기
4. 저장 시 `POST /api/admin/courses` 호출
5. 수정 시 `PUT /api/admin/courses/:classId` 호출
6. 삭제 시 `DELETE /api/admin/courses/:classId` 호출
7. 성공 후 목록 refetch

## 우선순위 판단

현재 프로젝트 마감 기준으로는 아래 순서가 좋다.

1. k3s DB, Backend, Frontend 배포 성공
2. `/api/health`와 `/api/courses`가 DB 연결 상태로 응답
3. 학생 수강신청/취소가 DB에 반영되는지 확인
4. 시간이 남으면 관리자 강의 CRUD 구현

관리자 CRUD는 포트폴리오 완성도를 높여주지만, 지금 단계에서 가장 중요한 것은 `Docker Hub image -> k3s deployment -> MariaDB 연동` 흐름을 먼저 성공시키는 것이다.
