## 현재 CRUD 구현 상태

### 구현되어 있는 기능

현재 Backend와 DB 기준으로 학생 수강신청 기능과 관리자 강의 관리 테스트용 CRUD가 구현되어 있다.

| 화면/기능 | DB 연동 여부 | 설명 |
|-----------|--------------|------|
| 강의 목록 조회 | 구현됨 | `GET /api/courses` |
| 내 수강 목록 조회 | 구현됨 | `GET /api/registrations` |
| 수강신청 | 구현됨 | `POST /api/registrations` |
| 수강취소 | 구현됨 | `DELETE /api/registrations/:classId` |
| DB health check | 구현됨 | `GET /api/health` |
| 관리자 강의 목록 조회 | 구현됨 | `GET /api/admin/courses` |
| 관리자 강의 추가 | 구현됨 | `POST /api/admin/courses` |
| 관리자 강의 수정 | 구현됨 | `PUT /api/admin/courses/:classId` |
| 관리자 강의 삭제 | 구현됨 | `DELETE /api/admin/courses/:classId` |
| 전공 목록 조회 | 구현됨 | `GET /api/majors` |

### 관리자 CRUD 테스트 방법

관리자 화면에서 아래 경로로 접근한다.

```txt
/admin/courses
```

확인할 것:

1. 페이지 진입 시 MariaDB의 `classes` 목록이 보이는지 확인
2. 강의ID, 강의명, 전공, 카테고리, 교수명, 좌석, 학점, 설명 입력
3. `강의 추가` 클릭
4. 테이블에 새 강의가 나타나는지 확인
5. 수정 아이콘 클릭 후 좌석/교수명 등을 바꾸고 `수정 저장`
6. 삭제 아이콘 클릭 후 테이블에서 제거되는지 확인

직접 API로 확인할 수도 있다.

```txt
GET    /api/admin/courses
POST   /api/admin/courses
PUT    /api/admin/courses/:classId
DELETE /api/admin/courses/:classId
```

### 현재 CRUD의 제한점

이번 CRUD는 배포/DB 연동 테스트를 위한 가벼운 구현이다.

- 관리자 로그인 권한 검증은 아직 붙어 있지 않다.
- 입력값 validation은 최소 수준이다.
- 삭제 시 `classes`의 FK cascade 정책에 따라 해당 강의의 수강신청 데이터도 함께 삭제될 수 있다.
- 실제 운영용이라면 admin auth, audit log, 삭제 전 등록 인원 확인, soft delete 정책을 추가하는 것이 좋다.

## 우선순위 판단

현재 프로젝트 마감 기준으로는 아래 순서가 좋다.

1. k3s DB, Backend, Frontend 배포 성공
2. `/api/health`와 `/api/courses`가 DB 연결 상태로 응답
3. 학생 수강신청/취소가 DB에 반영되는지 확인
4. 관리자 강의 CRUD가 DB에 반영되는지 확인

관리자 CRUD는 기본 테스트가 가능해졌지만, 지금 단계에서 가장 중요한 것은 `Docker Hub image -> k3s deployment -> MariaDB 연동 -> 관리자/학생 기능 확인` 흐름을 성공시키는 것이다.
