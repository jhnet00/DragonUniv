# Dragon University Platform 업무분담 정리

작성일: 2026년 6월 9일  
목적: 2인 프로젝트에서 rb와 jh가 맡은 업무를 실무 직무 관점으로 정리하고, 발표/README/인수인계에 사용할 수 있도록 문서화한다.

## 전체 방향

이 프로젝트는 한 사람이 처음부터 끝까지 만들 수도 있는 소규모 서비스지만, 포트폴리오 목적상 실제 운영 조직처럼 역할을 나누어 진행한다.

즉, 단순히 "프론트엔드 담당 / 백엔드 담당"으로 나누기보다 애플리케이션이 운영 환경에 올라가기까지의 흐름을 기준으로 나눈다.

```txt
Application code
  ↓
Container image
  ↓
Kubernetes manifest
  ↓
k3s cluster deployment
  ↓
Service / Ingress / DB integration
  ↓
Operation check
```

## rb 담당 범위

rb는 애플리케이션과 운영 환경 사이를 이어주는 역할을 맡는다.

### 1. Backend / DB 기반 기능

- MariaDB 스키마 설계 및 seed 데이터 정리
- 수강신청 API 구조 정리
- 강의 목록 조회, 신청, 취소 흐름 구현
- 잔여 좌석 계산 로직 정리
- 학생별 최대 신청 과목 수 / 학점 제한 로직 정리
- Backend가 DB 환경변수로 실행될 수 있도록 `.env.example` 정리

### 2. Frontend와 API 연결

- Frontend에서 Backend API를 호출할 수 있도록 `api.ts` 구성
- `VITE_API_URL` 기준으로 배포 환경 API 주소 주입 가능하게 정리
- 수강신청 페이지가 API 실패 시에도 mock data fallback으로 동작하도록 구조 유지
- 학생 페이지와 관리자 페이지의 화면 흐름 점검

### 3. Docker 이미지 준비

- `Frontend/Dockerfile` 작성
- `Backend/Dockerfile` 작성
- `.dockerignore` 작성
- Frontend는 Vite build 후 nginx 80번 포트로 정적 서빙
- Backend는 Node.js Express API를 4000번 포트로 실행
- jh가 manifest를 작성할 수 있도록 이미지 이름과 포트 명세 전달

이미지 기준:

| 서비스   | 이미지                   | 포트   |
| -------- | ------------------------ | ------ |
| Frontend | `dragon-frontend:latest` | `80`   |
| Backend  | `dragon-backend:latest`  | `4000` |

### 4. jh에게 넘겨야 하는 산출물

- Docker 이미지 이름
- 컨테이너 포트
- 필요한 환경변수 목록
- k3s import용 tar 파일 또는 Docker Hub 이미지 주소
- Backend DB 연결 조건
- Frontend API URL 조건

전달 예시:

```txt
Frontend image: dragon-frontend:latest
Frontend containerPort: 80
Frontend build arg: VITE_API_URL=/api

Backend image: dragon-backend:latest
Backend containerPort: 4000
Backend env:
- PORT=4000
- DB_HOST=<mariadb service name>
- DB_PORT=3306
- DB_USER=dragon_app
- DB_PASSWORD=dragonpass
- DB_NAME=dragon_university
- STUDENT_NUMBER=20251119
```

## jh 담당 범위

jh는 컨테이너화된 앱을 실제 운영 환경에 배포하는 인프라 구성을 맡는다.

### 1. VM / Linux 환경 구성

- VMware Fusion 또는 VirtualBox 기반 Ubuntu VM 준비
- Ubuntu 사용자, hostname, SSH 접속 설정
- k3s 설치 전 기본 패키지 업데이트
- 원격 접속 가능한 환경 구성

예시:

```txt
VM name: dragon-k3s
OS: Ubuntu ARM 또는 Ubuntu Server
SSH: ssh ruby@<VM_IP>
```

### 2. k3s 클러스터 구성

- k3s 설치
- 단일 노드 클러스터 Ready 상태 확인
- kubectl 명령어 사용 가능 여부 확인
- 이미지 import 또는 registry pull 방식 결정

확인 명령:

```bash
sudo kubectl get nodes
sudo k3s ctr images list
```

### 3. Kubernetes manifest 작성

jh는 rb가 전달한 이미지와 포트 정보를 기준으로 manifest를 작성한다.

필요한 파일 예시:

```txt
k8s/
  frontend-deployment.yaml
  frontend-service.yaml
  backend-deployment.yaml
  backend-service.yaml
  mariadb-deployment.yaml
  mariadb-service.yaml
  ingress.yaml
  configmap.yaml
  secret.yaml
```

### 4. Service / Ingress 라우팅

목표 라우팅:

```txt
sugang.drg/             -> Frontend
sugang.drg/register     -> Frontend SPA route
sugang.drg/admin        -> Frontend SPA route
sugang.drg/api          -> Backend API
```

Ingress 또는 reverse proxy에서는 `/api` 요청이 Backend service로 전달되도록 구성한다.

### 5. 배포 후 확인

- Pod가 정상 실행되는지 확인
- Service가 올바른 포트를 바라보는지 확인
- Ingress route가 정상인지 확인
- Frontend에서 Backend API 호출이 되는지 확인
- 수강신청 버튼 클릭 시 DB 데이터가 변경되는지 확인

확인 명령:

```bash
kubectl get pods
kubectl get svc
kubectl get ingress
kubectl describe pod <pod-name>
kubectl logs <pod-name>
```

## 둘이 같이 확인해야 하는 부분

### 1. DB 위치 결정

MariaDB를 어디에 둘지 결정해야 한다.

| 방식                   | 설명                        | 장점                           | 단점                                  |
| ---------------------- | --------------------------- | ------------------------------ | ------------------------------------- |
| k3s 내부 MariaDB Pod   | MariaDB도 Kubernetes에 배포 | 포트폴리오용으로 구조가 깔끔함 | PVC/storage 설정 필요                 |
| VM에 직접 MariaDB 설치 | Ubuntu VM에 DB 직접 설치    | 단순하고 빠름                  | Kubernetes 포트폴리오 포인트가 줄어듦 |
| Docker Compose MariaDB | VM에서 compose로 DB 실행    | 로컬 검증이 쉬움               | k3s 배포와 분리됨                     |

프로젝트 완성도 기준으로는 k3s 내부 MariaDB Pod + PVC 구성이 가장 좋다.

### 2. 이미지 전달 방식 결정

| 방식            | 설명                                     | 추천 상황               |
| --------------- | ---------------------------------------- | ----------------------- |
| tar import      | `docker save` 후 `k3s ctr images import` | 로컬 VM 실습, 빠른 검증 |
| Docker Hub push | registry에 push 후 manifest에서 pull     | 발표/협업/재현성 강조   |

현재는 로컬 실습이므로 tar import 방식으로 먼저 완료하고, 시간이 남으면 Docker Hub 방식으로 확장한다.

### 3. API URL 기준 맞추기

Frontend는 `VITE_API_URL`을 기준으로 API 주소를 받는다.

권장값:

```txt
VITE_API_URL=/api
```

Ingress에서 `/api`를 Backend service로 라우팅하면, 브라우저 기준으로 같은 도메인에서 API를 호출할 수 있다.
