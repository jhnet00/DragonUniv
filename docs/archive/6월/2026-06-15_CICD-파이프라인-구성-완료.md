## 작업 배경

k3s 배포가 완료된 상태에서 GitHub Actions(CI) + Jenkins(CD) 조합으로 자동 배포 파이프라인을 구성함.  
Jenkins VM(`dragon-jenkins`)은 이미 생성 및 Jenkins 설치 완료 상태였으며,  
Jenkins VM에서 k3s 클러스터를 제어할 수 있도록 연결하는 작업부터 시작함.

---

## 전체 아키텍처

```
코드 push (develop 브랜치, Frontend/ 또는 Backend/ 변경 시)
        ↓
GitHub Actions (CI) — GitHub 클라우드
  - Docker 이미지 빌드 (linux/amd64)
  - Docker Hub push (rubyjeenkim/dragon-frontend:latest, dragon-backend:latest)
        ↓
Jenkins (CD) — dragon-jenkins VM
  - 1분마다 GitHub develop 브랜치 polling
  - 새 커밋 감지 시 kubectl rollout restart 실행
        ↓
k3s (dragon-k3s VM)
  - Docker Hub에서 새 이미지 pull
  - frontend / backend 파드 롤링 업데이트
```

## 작업 내용

### 1. dragon-k3s SSH 키 인증 설정

Windows PC → dragon-k3s VM SSH 접속 시 비밀번호 없이 접속 가능하도록 설정.

```powershell
# 공개키 전송
scp -P 2222 "$env:USERPROFILE\.ssh\dragon-jenkins.pub" dragon@127.0.0.1:~/

# SSH 접속 후 authorized_keys 등록
mkdir -p ~/.ssh && cat ~/dragon-jenkins.pub >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys
```

`~/.ssh/config`에 IdentityFile 추가:

```
Host dragon-k3s
    HostName 127.0.0.1
    Port 2222
    User dragon
    IdentityFile ~/.ssh/dragon-jenkins
```

---

### 2. dragon-k3s NOPASSWD sudo 설정

SSH를 통해 sudo 명령어를 비밀번호 없이 실행할 수 있도록 설정.

```bash
echo "dragon ALL=(ALL) NOPASSWD:ALL" | sudo tee /etc/sudoers.d/dragon
```

---

### 3. k3s kubeconfig 추출 및 수정

k3s의 kubeconfig를 Windows PC로 가져와서 Jenkins VM이 접근할 수 있는 주소로 변경.

```powershell
# kubeconfig 추출
ssh dragon-k3s "sudo cat /etc/rancher/k3s/k3s.yaml" | ForEach-Object {
    $_ -replace 'server: https://127.0.0.1:6443', 'server: https://192.168.56.101:6443'
} | Set-Content "$env:USERPROFILE\k3s.yaml"
```

---

### 4. VirtualBox Host-Only 네트워크 구성

두 VM(dragon-k3s, dragon-jenkins)이 직접 통신하기 위해 Host-Only 네트워크 어댑터 추가.

| VM | 인터페이스 | 고정 IP |
|----|-----------|---------|
| dragon-k3s | enp0s8 | 192.168.56.101 |
| dragon-jenkins | enp0s8 | 192.168.56.102 |

각 VM에 netplan으로 정적 IP 고정:

```bash
# /etc/netplan/99-hostonly.yaml
network:
  version: 2
  ethernets:
    enp0s8:
      addresses:
        - 192.168.56.101/24  # dragon-jenkins는 192.168.56.102/24
```

```bash
sudo chmod 600 /etc/netplan/99-hostonly.yaml
sudo netplan apply
```

### 5. k3s TLS SAN 추가

Jenkins VM(192.168.56.102)에서 k3s API(192.168.56.101:6443)로 접근 시 TLS 인증서 오류 해결.

```bash
# dragon-k3s에서 실행
sudo bash -c 'echo "tls-san:
  - 192.168.56.101" > /etc/rancher/k3s/config.yaml'
sudo systemctl restart k3s
```

k3s 재시작 후 새 kubeconfig 재추출 및 Jenkins VM으로 전송.

### 7. Jenkins 컨테이너 재구성

Jenkins는 Docker 컨테이너로 실행 중이므로, kubectl과 kubeconfig를 컨테이너 내부에서 사용할 수 있도록 볼륨 마운트하여 재시작.

```bash
sudo docker stop jenkins && sudo docker rm jenkins

sudo docker run -d \
  -p 8080:8080 -p 50000:50000 \
  -v jenkins_home:/var/jenkins_home \
  -v /usr/local/bin/kubectl:/usr/local/bin/kubectl \
  -v /home/dragon-jenkins/.kube:/var/jenkins_home/.kube \
  --name jenkins jenkins/jenkins:lts
```

컨테이너 내부 kubectl 동작 확인:

```bash
sudo docker exec jenkins kubectl get nodes
# NAME         STATUS   ROLES           AGE   VERSION
# dragon-k3s   Ready    control-plane   12d   v1.35.5+k3s1
```

### 9. Jenkinsfile CD 파이프라인 작성

`Jenkinsfile`:

- `pollSCM('* * * * *')`: 1분마다 develop 브랜치 polling
- 새 커밋 감지 시 `kubectl rollout restart` 실행
- rollout status로 배포 완료 대기 (timeout 120s)

```groovy
pipeline {
    agent any
    triggers {
        pollSCM('* * * * *')
    }
    stages {
        stage('Deploy') {
            steps {
                sh 'kubectl rollout restart deployment/frontend -n dragon-univ'
                sh 'kubectl rollout restart deployment/backend -n dragon-univ'
                sh 'kubectl rollout status deployment/frontend -n dragon-univ --timeout=120s'
                sh 'kubectl rollout status deployment/backend -n dragon-univ --timeout=120s'
            }
        }
    }
}
```

Jenkins 파이프라인 잡 설정:
- 잡 이름: `dragon-deploy`
- Pipeline script from SCM → Git → `https://github.com/jhnet00/DragonUniv.git`
- Branch: `*/develop`
- Script Path: `Jenkinsfile`

## 트러블슈팅

### SSH 연결 불가 (k3s VM 멈춤)
- **문제:** dragon-k3s VM이 멈춰서 SSH 접속 불가
- **해결:** VirtualBox에서 VM 강제 재시작

### sudo 비밀번호 요구
- **문제:** `ssh dragon-k3s "sudo cat ..."` 실행 시 비밀번호 요구로 명령어 멈춤
- **해결:** `/etc/sudoers.d/dragon`에 NOPASSWD 설정

### VM 간 통신 불가 (NAT 한계)
- **문제:** Jenkins VM에서 `10.0.2.2:6443` 으로 k3s API 접근 불가 (NAT 환경 제약)
- **해결:** VirtualBox Host-Only 네트워크 어댑터 추가로 VM 간 직접 통신 구성

### TLS 인증서 오류
- **문제:** `x509: certificate is valid for 10.0.2.15, not 192.168.56.101`
- **해결:** k3s `config.yaml`에 `tls-san: 192.168.56.101` 추가 후 재시작

### Host-Only IP DHCP 만료
- **문제:** `dhclient`로 받은 IP가 약 10분 후 만료되어 인터페이스 DOWN
- **해결:** netplan으로 정적 IP 고정

### Jenkins 컨테이너 내부 kubectl 접근 불가
- **문제:** kubectl이 Jenkins 컨테이너 내부가 아닌 VM 호스트에만 설치됨
- **해결:** Docker 볼륨 마운트로 kubectl 바이너리와 kubeconfig를 컨테이너에 주입
