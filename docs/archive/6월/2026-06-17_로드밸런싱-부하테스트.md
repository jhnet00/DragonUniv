---

## 테스트 목적

수강신청 시간대의 트래픽 집중 상황을 가정하여, k3s + Traefik Ingress 환경에서 파드를 수평 확장(Scale Out)했을 때 요청이 균등하게 분산되는지 검증한다.

---

## 테스트 환경

| 항목 | 내용 |
|------|------|
| 클러스터 | k3s 단일 노드 (dragon-k3s, 192.168.56.101) |
| Ingress | Traefik (k3s 기본) |
| 테스트 대상 | `http://sugang.drg/` (Frontend) |
| 테스트 도구 | `scripts/simple-load-test.sh` (curl + xargs 기반) |

---

## 테스트 절차

### 1. 파드 스케일 업 (1개 → 3개)

```bash
kubectl scale deployment/frontend --replicas=3 -n dragon-univ
kubectl scale deployment/backend --replicas=3 -n dragon-univ
kubectl get pods -n dragon-univ
```

스케일 업 후 파드 상태:


Frontend 3개, Backend 3개 모두 Running 확인.

---

### 2. 부하 테스트 실행

```bash
# dragon-k3s VM /etc/hosts에 도메인 등록
echo '127.0.0.1 sugang.drg' | sudo tee -a /etc/hosts

# 부하 테스트 실행 (총 100 요청, 동시 접속 10)
curl -s https://raw.githubusercontent.com/jhnet00/DragonUniv/develop/scripts/simple-load-test.sh \
  | bash -s http://sugang.drg/ 100 10
```

## 결론

- 100개 요청 전체 성공 (0% 실패율)
- 3개 파드에 **34 / 33 / 33** 으로 균등 분산
- Traefik Ingress가 라운드로빈 방식으로 트래픽을 분산함을 확인
- 평균 응답시간 5ms로 안정적인 처리 성능 확인

수강신청 트래픽 집중 상황에서 `kubectl scale`로 파드를 수평 확장하면 Traefik이 자동으로 새 파드에 트래픽을 분산하여 부하를 처리할 수 있음을 검증하였다.
