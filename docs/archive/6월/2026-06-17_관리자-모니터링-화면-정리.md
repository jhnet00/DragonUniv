## 작업 배경

기존 운영 구조는 아래와 같다.

```txt
Docker 이미지
-> k3s에서 Frontend / Backend 컨테이너 실행
-> Traefik Ingress가 frontend/backend로 라우팅
-> sugang.drg 도메인으로 접근
```

모니터링은 별도 VM인 `dragon-monitoring`에서 Prometheus/Grafana를 실행하고,
`dragon-k3s` VM의 node-exporter 지표를 수집하는 구조로 진행했다.

관리자 화면에서는 단순 링크만 제공하는 것이 아니라,
프론트 화면 안에서 주요 상태를 바로 확인할 수 있어야 하므로 `/admin/monitoring` 화면을 정리했다.

## 오늘 작업 내용

### 1. `/admin` 관리자 대시보드 정리

관리자 첫 화면에서 모니터링 상태가 너무 늦게 보이는 문제가 있었다.

정리 방향:

- `/admin`에서는 전체 운영 상태를 요약해서 보여준다.
- `/admin/monitoring`에서는 더 자세한 모니터링 지표를 보여준다.
- 사이드바 메뉴에서 모니터링을 더 앞쪽에 배치한다.

관련 커밋:

```txt
8b85e0e feat: surface monitoring summary on admin dashboard
```

### 2. `/admin/monitoring` 화면 개선

초기에는 Grafana iframe embed를 시도했지만,
권한 설정, public dashboard, dashboard 변수, `No data` 문제 때문에 발표 직전 안정성이 낮았다.

그래서 관리자 프론트에서 직접 다음 정보를 보여주는 방식으로 정리했다.

- Prometheus target 상태
- Prometheus API query 시도
- node-exporter 기반 주요 지표 표시
- CPU/Memory/Disk/Network/Process 상태 카드
- gauge 형태의 시각화
- 위험도 판단
- AI Report 형태의 운영 요약

관련 커밋:

```txt
6e70443 feat: surface prometheus monitoring status
7c5f5c2 feat: refine monitoring dashboard presentation
```

### 3. Prometheus 사용 방식 정리

프론트 화면은 Prometheus를 사용하지 않는 것처럼 보이면 안 되므로,
아래 순서로 동작하도록 정리했다.

```txt
1. /prometheus/api/v1/targets 조회
2. Prometheus target 상태를 화면에 표시
3. /prometheus/api/v1/query로 주요 metric query 시도
4. Prometheus query 결과가 비어 있으면 화면이 깨지지 않도록 node-exporter 값으로 표시
```

즉, 화면에는 Prometheus target/scrape 상태가 명확히 표시되고,
지표 값은 발표 안정성을 위해 node-exporter fallback도 허용한다.

나중에 완전히 Prometheus 값만 사용하려면 Prometheus query 결과가 정상적으로 나오도록
scrape config와 label을 다시 확인하면 된다.

확인용 명령:

```bash
curl "http://192.168.232.135:9090/api/v1/targets"
curl "http://192.168.232.135:9090/api/v1/query?query=up"
curl "http://192.168.232.135:9090/api/v1/query?query=node_load1"
```

### 4. 화면에서 제거/수정한 부분

수정 전 문제:

- `Metric query: Prometheus query returned no node metrics` 문구가 화면에 표시되어 오류처럼 보임
- chart가 `자세히보기` 안에 접혀 있어서 한눈에 보이지 않음
- raw PromQL query가 그대로 보여 발표 화면에서 지저분해 보임
- `Low / Medium / High` 숫자 카드만 있으면 의미가 부족함

수정 후:

- Prometheus query 실패 문구는 사용자 화면에서 숨김
- 주요 지표 chart를 항상 펼친 상태로 표시
- raw query 문구 제거
- 단순 위험도 카드를 AI Report 형태로 변경
- 각 지표에 `정상`, `주의`, `위험`, `확인 중` 상태 표시

## 오늘 겪은 이슈와 해결

| 이슈 | 원인 | 해결 |
|------|------|------|
| Grafana iframe/public dashboard가 안정적으로 보이지 않음 | 권한, public dashboard, dashboard 변수 문제 | 프론트에서 자체 monitoring card/gauge 구성 |
| Grafana dashboard가 `No data`로 표시됨 | dashboard 변수 `job`, `instance`, `nodename` 불일치 가능성 | `job=node-exporter`, `instance=192.168.232.133:9100` 기준으로 확인 |
| Prometheus query 결과가 비어 있음 | Prometheus scrape label 또는 query 대상 불일치 가능성 | target 상태는 Prometheus로 표시하고, 값은 node-exporter fallback 허용 |
| raw PromQL이 화면에 노출됨 | 상세 확인용 query를 카드에 그대로 표시했음 | 발표용 화면에서는 query 문구 제거 |
| 위험도 표시가 의미 부족 | Low/Medium/High 숫자만 표시됨 | AI Report 형태로 상태 판단 문구 추가 |

## CI/CD 확인 포인트

팀원이 CI/CD를 완료했다고 했으므로 GitHub에서 아래를 확인한다.

```txt
GitHub Repository
-> Actions
-> workflow 실행 여부
-> Docker image build/push 성공 여부
-> Jenkins 또는 VM/k3s 배포 단계 존재 여부
```

중요한 구분:

```txt
CI만 완료:
- Docker 이미지 build/push까지 자동
- VM에서는 수동으로 pull/restart 필요

CD까지 완료:
- Jenkins 또는 GitHub Actions가 VM/k3s에 접속
- kubectl rollout restart 또는 kubectl apply 실행
- push 이후 VM 서비스가 자동 갱신됨
```

VM과 자동 연결되어 있는지 확인할 키워드:

```txt
ssh
kubectl
rollout restart
kubectl apply
helm upgrade
Jenkins webhook 또는 polling
```

## env 파일 관련 메모

env 파일은 직접 작성 예정이다.

주의:

- `.env`에는 실제 비밀번호, token, secret을 넣을 수 있다.
- `.env`는 Git에 올리지 않는다.
- 문서에는 실제 secret 값을 남기지 않는다.
- 필요한 경우 `.env.example`만 만들어 key 이름만 공유한다.
