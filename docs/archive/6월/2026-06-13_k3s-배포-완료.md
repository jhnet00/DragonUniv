## 작업 배경

VirtualBox VM(`dragon-k3s`)에 k3s가 설치된 상태에서 Frontend, Backend, MariaDB를 k3s에 배포하고 Traefik Ingress를 통해 `sugang.drg` 도메인으로 접근 가능한 환경을 구성함.

---

## 작업 내용

### 1. Docker Hub 이미지 확인

rb가 Docker Hub에 올린 이미지:

```
rubyjeenkim/dragon-frontend:latest
rubyjeenkim/dragon-backend:latest
```

초기 이미지가 arm64 아키텍처로 빌드되어 amd64 VM에서 `exec format error` 발생.  
rb가 amd64로 재빌드 후 정상 동작 확인.

---

### 2. VM에 Docker 설치

```bash
sudo apt install -y docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
newgrp docker
```

---

### 3. k3s namespace 생성

```bash
sudo kubectl create namespace dragon-univ
```

---

### 4. manifest yaml 작성

`k3s/` 폴더 (기존 `k8s/` → `k3s/`로 이름 변경):

| 파일 | 내용 |
|------|------|
| `mariadb.yaml` | MariaDB StatefulSet, Service, Secret, ConfigMap, 스키마/시드 데이터 |
| `frontend-deployment.yaml` | Frontend Deployment + Service |
| `backend-deployment.yaml` | Backend Deployment + Service (환경변수 포함) |
| `ingress.yaml` | Traefik Ingress (`/api` → backend, `/` → frontend) |

---

### 5. k3s 배포

```bash
sudo kubectl apply -f k3s/mariadb.yaml
sudo kubectl apply -f k3s/frontend-deployment.yaml
sudo kubectl apply -f k3s/backend-deployment.yaml
sudo kubectl apply -f k3s/ingress.yaml
```

---

### 6. 트러블슈팅

#### arm64 아키텍처 불일치
- **문제:** `exec format error` — rb가 Apple Silicon(arm64)에서 빌드한 이미지가 amd64 VM에서 실행 안 됨
- **해결:** rb가 `--platform linux/amd64` 옵션으로 재빌드 후 Docker Hub 재업로드

#### Ingress ingressClassName 오류
- **문제:** `ingressClassName: nginx` 설정이지만 k3s 기본 Ingress Controller는 Traefik
- **해결:** `ingressClassName: traefik` 으로 변경

#### /api 라우팅 오류
- **문제:** `/api/courses` 요청이 backend로 가지 않고 frontend HTML 반환
- **원인:** nginx ingress 전용 `rewrite-target` annotation이 Traefik에서 무시됨
- **해결:** annotation 제거 후 `pathType: Prefix`로 단순화

## 비고 / 후속 과제

- 현재 `sugang.drg`는 로컬 PC에서만 접근 가능 (hosts 파일 등록 기준)
- 외부 접근은 공인 IP + 도메인 DNS 연결 필요
- Nginx Ingress Controller 대신 Traefik 사용 중 (k3s 기본값)
- 다음 단계: Jenkins CI/CD, Prometheus/Grafana 모니터링 구성 (rb 담당)
